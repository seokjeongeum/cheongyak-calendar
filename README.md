# 청약 한눈에

거주 지역에 맞춰 전국의 공식 분양·민간임대 청약 공고를 가장 가까운 접수 마감일순으로 보는 웹앱입니다. 주택형별 가격·경쟁률과 분양가상한제 여부를 목록에서 바로 보여주며, 입력한 조건으로 참고용 자격 진단을 실행합니다. 공공임대는 화면의 목록·달력·후보 집계에서 제외하고 수집된 원본은 이력으로 보존합니다.

## 무료 웹 배포

[Render 무료 웹 배포 연결](https://render.com/deploy?repo=https://github.com/seokjeongeum/cheongyak-calendar/tree/work)에서 웹·API를 배포하고 [Neon Free](https://console.neon.tech/)의 PostgreSQL을 연결합니다. 배포 설정은 `Free` 웹 서비스 한 개만 생성합니다. 사용자 PC의 Git·Docker 업데이트는 필요하지 않습니다. 계정 연결과 수집 자동화 활성화 방법은 [무료 웹 배포 안내](docs/free-hosting.md)에 있습니다.

**데이터 출처 → API 연결 설정**에서 서비스별 발급 링크를 열고 키를 저장합니다. API 키는 서버의 PostgreSQL에 보관합니다. 설정 변경에는 Render가 생성한 관리자 인증키가 필요합니다. 개인 조건은 웹 주소별 브라우저 저장소에만 남으므로 기존 localhost의 입력과 웹사이트의 입력은 별개입니다.

무료 웹 서버는 15분 동안 사용하지 않으면 쉬며, 다시 열 때 약 1분이 걸릴 수 있습니다. 수집기는 별도 GitHub Actions에서 3시간 주기로 실행합니다. 워크플로를 기본 브랜치에 적용하고 같은 DB를 연결한 뒤 활성화되며, 실행 지연과 무료 한도가 적용됩니다. 기존 Railway 배포는 무료 운영 조건에 맞춰 제거했습니다.

## 로컬 개발·기존 Docker 설치

```bash
cp .env.example .env
# .env에서 POSTGRES_PASSWORD만 변경합니다. API 키는 실행 후 화면에서 설정합니다.
docker compose up --build
```

웹: http://localhost:8080 · API: 웹 경유 `/api/` · API 문서: http://localhost:8080/api/docs

### 기존 localhost 설치 업데이트

기존 프로젝트 폴더에서 실행합니다. PostgreSQL 볼륨과 기존 `.env`는 유지하며 API·수집기·웹을 새 코드로 다시 만듭니다.

```bash
git pull --ff-only origin work
docker compose up -d --build api worker web
```

아래 관리자 인증키 발급을 로컬 Docker에서 한 번 실행한 뒤 [데이터 출처](http://localhost:8080/#coverage)의 **API 연결 설정**을 엽니다. 클라우드에서 발급한 인증키는 로컬 데이터베이스의 인증키와 별개입니다.

API 키는 화면의 **데이터 출처 → API 연결 설정**에서 입력·교체·삭제합니다. 각 입력 옆의 **활용신청·키 발급** 링크로 해당 공공데이터 서비스에 바로 이동할 수 있습니다. 일반 인증키(Decoding)를 사용하고, 공통 키를 쓰더라도 각 서비스의 활용신청 승인이 필요합니다. Gemini에는 [Google AI Studio 키 발급](https://aistudio.google.com/apikey) 링크를 제공합니다.

최초 설정 전에 서버에서 관리자 인증키를 발급합니다. API 키를 `.env`에 넣거나 수집기를 재생성할 필요는 없습니다.

```bash
docker compose exec api python -m app.integration_settings
```

출력된 관리자 인증키를 화면에 입력한 뒤 연결 설정을 저장합니다. 이 명령을 다시 실행하면 관리자 인증키가 교체되고 기존 인증키는 무효화됩니다. API 키 원문은 서버 PostgreSQL에 저장되므로 데이터베이스와 백업을 비공개로 관리하세요. 조회 API는 연결 여부만 반환하며, 키와 관리자 인증키는 브라우저 저장소에 저장하지 않습니다. 화면을 닫으면 입력한 키를 지웁니다. 공개 운영에서는 HTTPS로 접속하세요.

저장된 설정은 환경변수보다 우선하며, 다음 3시간 수집부터 적용됩니다. 이미 진행 중인 요청은 종료 후 다음 수집에서 새 키를 사용합니다. 삭제한 키는 환경변수로 복원되지 않습니다. 기관 전용 키가 없으면 공통 키를 사용합니다. 기존 환경변수는 이전 설치와의 호환을 위해 계속 읽지만 새 설치에는 필요하지 않습니다.

공공데이터 키가 없으면 인증이 필요한 출처는 연결 미설정으로 표시하고 SH·GH 공개 게시판은 계속 수집합니다. 경쟁률 API가 없거나 인증 실패 시 APT 공개 경쟁률 화면을 보완 출처로 사용합니다. 승인 여부와 사용 기간은 각 포털 신청 내역에서 확인하세요.

Gemini 문서 추출은 선택 사항입니다. 키를 입력해도 **청구를 사용하지 않는 Google 프로젝트임을 확인**하는 체크 없이는 호출하지 않습니다. 키 변경 시 이 확인을 다시 받습니다. 프로젝트 과금 상태를 자동으로 검증하지는 않습니다. 무료 한도 초과 시 대기하며 유료 모델로 전환하지 않습니다. 공개 공고문만 제출하며 개인 조건은 전송하지 않습니다. 공개 공고문과 응답은 Google 제품 개선에 사용될 수 있습니다.

## 경쟁률·해당지역 마감 표시

경쟁률 카드에는 주택형·순위·거주지역별 모집 수, 접수 수, 공식 경쟁률 표시, 청약결과와 원문·조회 시각을 표시합니다. `-`는 미공개, `(△57)`은 미달 57세대로 구분합니다. 특별공급 신청 수 등 경쟁률과 다른 지표는 원래 기준을 유지합니다.

공식 **1순위 해당지역 마감(청약 접수 종료)** 결과가 있거나, **일반공급 전량 해당지역 우선배정 + 공식 1순위 마감 + 같은 주택형 해당지역 접수 수가 모집 수 이상**이 모두 확인된 주택형은 기타지역 배정 기회 종료로 판단합니다. 특별공급 배정 비율을 일반공급에 적용하지 않습니다. 경쟁률 1 이상이나 일반적인 청약 접수 종료만으로 판단하지 않으며 원래 결과와 앱의 계산 근거를 구분합니다. [실제 해당지역 마감 사례](https://www.applyhome.co.kr/ai/aia/selectAPTCompetitionPopup.do?houseManageNo=2026000399&pblancNo=2026000399), [광명 비교 사례](https://www.applyhome.co.kr/ai/aia/selectAPTCompetitionPopup.do?houseManageNo=2026000453&pblancNo=2026000453)를 대조했습니다.

**내 조건 설정 → 청약통장**에서 통장 종류와 민영·국민주택별 **순위기산일**, 예치금·납입인정 내역을 입력합니다. 공고의 공식 주택 구분과 검증된 요건을 각각 비교하며 새 사실은 미확인으로 시작합니다. 기간만으로 1순위를 확정하지 않고, 1순위 미충족을 자동으로 2순위로 바꾸지 않습니다. 공식 거주 조건이 불명확하면 카드의 **이 공고의 청약 지역**에서 공고문을 확인한 지역을 선택합니다. 순위와 공고별 지역 선택은 브라우저에만 저장하며 기타경기는 기타지역과 구분합니다. 신청 불가 공고·접수일·경쟁률도 계속 표시합니다. 모든 모집 유형·주택형이 확정 불가일 때 카드에 **내 조건으로 신청 불가**를 표시하고, 일부만 불가이면 해당 유형·주택형·경쟁률 행만 회색으로 구분합니다. 가격·공식 근거·조건 입력은 계속 사용할 수 있습니다.

순위·지역 미확인, 결과 미게시, 불완전한 주택형 목록, 최신 수집 실패 또는 조회 후 6시간 경과 시 현재 접수의 지역 마감을 확정하지 않습니다. 경쟁률은 기존 3시간 수집 주기를 따르며, 관련 정정으로 근거가 무효화되면 마감 표시를 해제합니다. 표시 건수·행 수·더 보기에는 회색 항목도 포함하고, 신청 가능한 지역 후보 수는 따로 계산합니다. 달력은 해당 날짜의 모든 접수가 확정 불가인 경우 흐린 점을 표시합니다.

### 종료된 공고의 결과 보기

**경쟁률·청약결과** 탭은 기본 최근 90일의 접수 기간과 겹치는 공고 중 저장된 공식 경쟁률이 있는 공고를 보여줍니다. 접수 기간을 바꿀 수 있으며 접수 종료일 최신순으로 표시합니다. 기타지역 배정 기회가 끝난 주택형도 모든 경쟁률 행과 가격을 유지하고, 확인된 기타지역 사용자에게 회색 표시와 배정·마감 근거를 제공합니다. 종료 결과의 마감 판단은 통장 순위 확정·6시간 제한과 분리합니다. 이전 숨김 설정은 적용하지 않습니다. 접수 일정의 달력은 계속 오늘 이후만 보여줍니다.

수집기는 종료 후 90일까지 미공개 결과·정정을 재확인합니다. 최근 수집 실패·6시간 경과 시에도 저장된 공식 결과와 조회 시각은 남습니다. 관련 정정으로 근거가 무효화돼 재확인 중이면 결과의 지역 마감 판정을 해제합니다. 6시간 제한과 남은 공급유형 확인은 현재 접수의 신청 불가 판정에 적용합니다.

`GET /api/notices?view=results&start=YYYY-MM-DD&end=YYYY-MM-DD&exclude_public_rental=true`는 공식 경쟁률 여부를 페이지네이션 전에 적용합니다. `view` 기본값은 `schedule`로 기존 요청 동작을 유지합니다. 결과 조회는 `application_only=true`와 같은 접수 기간 겹침 기준을 사용합니다. 목록·상세의 `application_end_date`는 당첨 발표·계약일을 제외한 마지막 공식 접수일입니다.

## 사실 입력·자격 설명

- 상단과 조건 설정의 시도·시군구는 연결된 드롭다운입니다. [행정안전부 2026-09-30 자료](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=129824)를 시도·시군구·상위 도시 수준으로만 브라우저에 포함합니다. 읍면동·리 입력이나 지역 조회 요청은 없습니다. 도시 조건은 산하 구와 비교하며, 경계 변경으로 확인할 수 없는 과거 지역은 재선택·추가 확인으로 안내합니다.
- 시도·시군구 연속 거주 시작일을 따로 입력합니다. 산하 구를 선택한 경우 상위 도시 전체의 연속 거주일도 별도로 확인하며 다른 범위의 날짜로 대체하지 않습니다.
- 세대주, 배우자·등본 관계, 본인·배우자·확인 대상 가족의 현재·과거 주택·분양권·입주권·공유지분을 묻습니다. 소유자·관계·나이·주택 종류·면적·공식 가격·취득/처분 경위와 날짜로 [제53조](https://www.law.go.kr/법령/주택공급에관한규칙/제53조)의 12가지 경로를 비교하며, 완료하지 않은 처분·공부 정리는 인정하지 않습니다. 60세 이상 직계존속 등 공급유형별 적용 차이를 구분하고 부족한 사실만 추가 질문합니다. 상세 기준은 [소유 사실과 법령 비교](docs/ownership-rules.md)에 기록했습니다.
- 민영·국민주택 순위기산일은 은행 또는 청약홈의 순위확인서에서 각각 확인합니다. [국민 제27조](https://www.law.go.kr/법령/주택공급에관한규칙/제27조), [민영 제28조](https://www.law.go.kr/법령/주택공급에관한규칙/제28조)의 기준과 공고의 기간·예치금·납입 인정 요건을 분리합니다. 순위 요건 확보 상태는 전체 자격 완전성과 분리하며, 공식 요건과 사실을 모두 충족하면 **1순위 조건 충족**을 확정합니다. 전용면적별 예치금이 다르면 주택형별로 비교하고, 공고 기준일의 금액·인정내역을 확인합니다. 은행 인정값은 확인된 입력으로 취급하며 과거 금액 비교에는 마지막 변경일이나 실제 저장 이력을 사용합니다. 오피스텔 등 순위 적용이 없는 공고에는 아파트 순위기산일을 요구하지 않습니다.
- 특별공급 자격을 직접 고르게 하지 않습니다. 생년월일·혼인·자녀·임신·입양·소유·당첨 이력의 공통 사실을 입력하고, 모집 유형과 사실에 따라 부양·소득세·추천·이전기관 등 추가 질문을 보여줍니다. 신혼부부·신생아·생애최초·다자녀·노부모부양·기관추천·청년·이전기관 종사자·기타를 구분해 여러 실제 모집 유형을 동시에 비교합니다. 미확인 특별공급이 남아 있으면 경쟁률만으로 공고 전체의 신청 불가를 확정하지 않습니다.
- 금액은 `60,000,000`처럼 표시하며 브라우저에는 원 단위 정수 문자열로 저장합니다. 연 소득·총자산 외에 공고가 요구하는 월평균소득·부동산·자동차 값을 별도로 입력합니다. 연 소득을 12로 나눠 법정 월평균소득으로 인정하지 않습니다.
- 카드에서 확인된 조건과 구체적인 불일치·추가 입력 질문, 거주지 기반 접수일 후보의 선정 이유를 보여줍니다. **유형별 근거**는 공통 조건을 한 번 표시하고 실제 공급유형·주택형별 차이를 펼칩니다. 값이 있는 내 입력 → 요구값 → 기준일 → 판단 이유 → 공식 원문을 표시하며, 미입력 안내는 해당 조건 입력 단계로 연결합니다. 수집기가 조건을 읽지 못한 경우는 공식 조건 미공개로 표현하지 않습니다.
- 프로필은 `cheongyak-profile-v5`로 브라우저에서만 이전합니다. 기존 거주·통장·금액·소유 기록은 보존하며 예전 세대 범위 자기확인·세대원 수·소유 예외 답변을 새 가족 목록이나 인정 결과로 만들지 않습니다. 이름 없이 가족 관계와 본인/배우자 등본 위치를 입력하면 [제2조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032749671)에 따라 주택 보유를 함께 확인할 사람·포함 이유·계산된 인원 수를 표시합니다. 별도 주소의 법률상 배우자를 포함하고, 형제자매·동거인은 같은 등본이라는 이유로 포함하지 않습니다. 소득 산정 가구원 수는 별도 입력입니다. 현재 사실은 한국 시간 오늘 기준입니다. 과거 공고는 사실별 마지막 변경일과 저장된 실제 이력을 사용하며, 당시 상태를 모르면 판단을 보류합니다. PostgreSQL 공고·가격·경쟁률 이력은 유지합니다.

### 무순위 공고의 신청 조건

목록·상세의 `application_method`와 `application_method_evidence`로 공식 **무순위 사후접수·임의공급·계약취소 후 재공급**을 구분합니다. 최초 아파트 공고일과 이번 접수의 자격 기준일을 별도로 보존하며, 청약통장·순위 적용 없음이 신청 자격 없음이라는 뜻은 아닙니다. 연령·국적·거주지역·무주택·세대주·해외 체류·해당 사업의 당첨·계약 이력·청약 제한을 검증한 공고 범위에서 비교합니다.

세종 우미 린·신림스카이20차의 무주택 세대구성원 조건과 강변역 센트럴 아이파크의 무주택 세대주 조건을 문서 해시별 검토로 구분합니다. 제한 조회는 확인 대상 범위와 조회 기준일을, 당첨·계약 이력은 최초 사업번호를 함께 저장합니다. 현재 사실을 과거 기준일에 자동 적용하지 않습니다. 필요한 공식 조건과 입력이 모두 확보된 공급유형만 신청 가능성을 판정하며, 변경 문서·미지원 예외·미입력은 추가 확인으로 남깁니다. 이 계산과 가족·소유·제한 정보는 브라우저에서만 저장·실행합니다.

공식 조건의 분기·예외·시행기간 및 완전성 규약은 [규칙 인터페이스](docs/qualification-rules.md)에 정리했습니다.
실제 민영·국민·신혼희망타운 공고의 값·단위·페이지·문서 해시 대조 기록은 [공식 문서 파서 검증](docs/official-parser-validation.md)에서 확인할 수 있습니다.

### 신청지역과 실제 모집유형

신청할 수 있는 지역과 해당지역 우선권은 별도로 비교합니다. 카드는 `해당지역`, `기타지역`, 구분이 없는 공고의 `신청지역 충족`, `신청지역 밖`과 구체적인 이유를 표시합니다. 제주 1년 미만 거주는 기타지역이지만 다른 시도 거주는 신청지역 밖입니다. 천안 외 충남·대전·세종 거주자는 기타지역이며, 화성시는 이 신청범위에 포함되지 않습니다. 군인 예외가 명시된 공고는 현재 복무 여부·복무기간·기준일의 사실을 별도로 확인합니다.

공식 공급표의 주택형·유형별 모집 수를 `offered_supplies`로 반환하고, 0명인 조합은 진단하지 않습니다. 탕정 푸르지오 리버파크는 생애최초만, 고양 장항 아테라는 일반공급과 노부모부양만 비교합니다. 시군구 조건은 상위 도시 관계로 비교하며, 최초 사업 공고일과 이번 접수의 자격 기준일·계약일 기준을 분리합니다. 과거 기준일 이후 이사한 경우 저장된 주소 이력만 사용하며, 이력이 없으면 과거 지역을 판단하지 않습니다. 공고별 이전 주소를 추가로 묻지 않습니다.

공공분양은 실제 문서의 순위형 청약·신혼희망타운·선착순·잔여주택 매각·자격완화 조건을 사용합니다. 청약통장이 불필요하거나 유주택자를 허용하는 공고에 국민주택 1순위·무주택 조건을 추가하지 않습니다. A17의 신혼·예비신혼·한부모 유형은 청약홈과 LH에서 같은 문서 해시를 사용하고, 6개월·6회 요건을 일반공급 순위와 분리합니다. 월평균소득과 인정 부채를 차감한 순자산은 연 소득·총자산으로 대체하지 않습니다.

확인된 부분 조건은 바로 비교하며, 필수 조건·분기·예외를 확보한 유형만 전체 가능성을 확정합니다. 문서 처리가 부족한 내용은 공고당 한 번 안내하고 상세에서 남은 항목과 처리 단계별 원인을 제공합니다. 빈 일반공급 진단을 만들어 반복 표시하지 않습니다. 현재 공고의 실제 자료·테스트·확보 상태는 [지역·공공분양 검증 기록](docs/regional-qualification-validation.md)과 [공고별 재처리 기록](docs/qa/v5-final-active-2026-10-05.json)에서 확인할 수 있습니다.

현재·예정된 모든 분양 공고를 로컬 문서 파서로 재처리할 수 있습니다. Gemini 호출과 개인정보 입력은 없습니다.

```bash
docker compose exec -T api python -m app.extract.reprocess --active --all --sales-only --report /tmp/qualification-audit.json
```

## 구성

- `web/`: React·TypeScript. 오늘 이후 접수 목록, 작은 달력, 분양가상한제 필터, 주택형별 가격, 브라우저 내 자격 진단.
- `api/app/`: FastAPI와 PostgreSQL 데이터 저장. 공고·가격·규칙 근거·출처 상태를 공개 API로 제공.
- `api/app/ingest/`: 청약홈·마이홈 및 기관별 공식 공고 수집, 중복 및 정정공고 추적. 3시간마다 실행.
- `api/app/extract/`: 공식 공개 PDF/HWP/HWPX의 로컬 조건 파서와 선택적인 Gemini 후보 추출. 로컬 처리는 Gemini 키·무료 한도와 분리하며, Gemini에는 공개 공고문만 전송하고 후보값에는 미검증 표시를 붙입니다.

사용자 거주지·세대·소득·자산 정보는 브라우저에만 저장됩니다. 서버 API와 Gemini에 사용자 프로필을 보내지 않습니다. 진단 결과는 기관의 최종 심사가 아니며, 공고별 확인이 필요한 조건을 별도로 표시합니다.

## 공식 자료와 표시 기준

- [청약홈 분양정보 API](https://www.data.go.kr/data/15098547/openapi.do)의 APT, 오피스텔·도시형 등, 잔여세대, 공공지원 민간임대, 임의공급 연산을 조회합니다. APT 주택형 가격의 `공급금액`은 [한국부동산원 설명](https://www.data.go.kr/data/15101047/fileData.do)에 따라 **주택형별 분양최고금액**, 단위는 **만원**으로 해석해 원으로 변환합니다. 임대 공고의 모호한 공급금액을 보증금으로 바꾸어 표시하지 않습니다.
- [마이홈 공공주택 API](https://www.data.go.kr/data/15108420/openapi.do)의 임대·분양 조회 연산과 공식 상세 공고를 사용합니다. 포털 설명문은 임대를 중심으로 쓰여 있으나 현재 공개된 API 명세에는 공공분양 조회 연산도 있습니다. LH·iH 공식 API와 SH·GH 공고 게시판을 보완 출처로 수집합니다.
- 일정은 공식 자료에 날짜가 있을 때만 접수 유형별로 표시합니다. 화면에는 오늘부터 접수 가능한 공고를 싣고 종료된 접수 유형은 숨깁니다. 접수일이 없는 공고의 원본은 API와 수집 이력에 보존하며 날짜를 추정하지 않습니다. 모든 날짜 판단과 갱신 시각은 한국 시간 기준입니다.
- 시작일이 지났지만 접수 종료일이 남은 공고는 **현재 접수 중**으로 표시합니다. 과거 달과 오늘 이전 날짜를 선택할 수 없으며, 연도를 넘는 일정은 연도를 명시합니다. 공식 시작일과 모집공고일은 근거에 보존합니다.
- 검토된 공식 문서 형식에서 명시된 조건을 읽는 로컬 파서는 값·단위·공급유형·기준일과 문서 해시·페이지·파서 버전을 보존합니다. 지원되지 않는 분기·예외가 남으면 전체 조건 확인으로 처리하지 않습니다. Gemini가 추출한 가격·조건 후보는 **미검증**이며 후보만으로 `조건상 가능성 있음` 판정을 만들지 않습니다.

## 운영 확인

`GET /api/coverage`에서 출처별 `pending`·`running`·`ok`·`partial`·`error`·`disabled` 상태, 마지막 시도·성공 시각, 저장 건수와 원인을 확인할 수 있습니다. 수집 중에도 이전 성공 시각과 저장 건수를 유지합니다.

`GET /api/notices?start=YYYY-MM-DD&end=YYYY-MM-DD`는 목록 카드에 필요한 모든 주택형 가격·경쟁률과 근거를 포함합니다. `competitions`는 경쟁률 행이고 `competition`은 마지막 시도·성공 시각, 전체 주택형 확인 여부와 수집 상태, 정정으로 인한 `proof_invalidated` 여부입니다. 상세 API에도 같은 정보를 제공합니다. 공식 `housing_kind` (`private`·`national`·`not_applicable`·`unknown`), 분류 원문 `housing_kind_evidence`, `rank_applicability`, `qualification_context`, `application_method`와 `application_method_evidence`도 포함합니다. 신청 방식은 `apt_ranked`·`unranked_after`·`optional_supply`·`cancelled_resupply`·`first_come`·`officetel`·`unknown`으로 구분합니다. 주택 종류와 아파트 순위 적용 여부를 분리하며 공급기관이나 ‘공공분양’ 표기는 분류 근거로 사용하지 않습니다. 가격의 `exclusive_area_sqm`은 공식 전용면적이고, `area_basis`로 기존 면적의 기준을 구분합니다. 분류·규제지역·순위 완전성·신청 지역·일반공급 지역 배정·청약신청금은 규칙 JSON 메타데이터로 보존합니다. 선택 옵션 `exclude_public_rental`과 `application_only`는 기본값이 `false`이며, 화면은 둘 다 `true`로 요청합니다. 제외 조건은 페이지네이션 전에 적용하므로 `total`과 더 보기 결과가 일치합니다. 조회 시작일 전에 시작한 접수의 표시용 `sort_date`는 조회 시작일로 보정하고 원래 공식 일정은 보존합니다.

화면이 보이는 동안 대기·진행 상태는 30초, 완료 상태는 5분마다 확인합니다. 수집 성공 시각이 바뀌면 목록과 달력을 갱신하고 수동 새로고침을 지원합니다. **창·탭 복귀 자체로는 API를 조회하지 않으며**, 한국 날짜와 경쟁률 6시간 유효시간만 보정합니다. 실제 날짜가 바뀌면 변경된 조회 범위로 접수일을 다시 조회합니다. 배경 조회 중 기존 카드·펼친 근거·입력 중인 조건은 유지합니다. 한국 시간 자정이 지나면 기준일을 갱신합니다. 거주지·전입일·필터는 그대로 유지합니다.

청약홈·마이홈·LH·iH 실데이터 대조에는 각 공공데이터 API의 유효한 서비스 키가 필요합니다. 키가 없는 출처는 `연결 미설정`으로 남으며 예시 공고와 실공고는 섞이지 않습니다.

### 반복 질문과 입력 성능 (프로필 v5)

- 확인한 기준일, 개인 예정 계약일, 공고별 이전 주소·당첨·계약 질문과 통장 전환 인정 질문을 제거했습니다. 시도·시·군 거주 시작일을 사용하고 일반구는 상위 도시로 통합합니다. 명시적인 구 단위 공고만 세부 구를 받습니다. 기존 v4 관측일은 마지막 변경일로 변환하지 않습니다.
- 필요한 과거 조건에만 마지막 변경일·변경 이력 없음·날짜 모름을 묻습니다. 당첨·예비당첨·계약·추가 입주자 계약은 공통 이력에서 사람·최초 사업·종류·날짜를 연결합니다. 면제된 이력은 질문하지 않습니다.
- 목록·상세 `contract_schedule`은 공식 계약 일정·근거·문서 해시를 제공합니다. 상시 계약은 ‘오늘 계약한다면’, 예정 기간은 시작일에 ‘현재 입력이 유지될 때’로 비교합니다. 게시 종료일과 개인 예정일은 사용하지 않습니다.
- 미혼인 필수 혼인 경로는 불일치로 표시하며 혼인기간·배우자 질문을 생성하지 않습니다. 예비신혼·한부모 경로는 별도로 유지합니다. 청주지북은 검토한 파일 해시의 성년·국내 거주·국적·임직원 조건을 모두 충족하면 가능성을 표시합니다.
- 입력 초안은 즉시 반영하고 300ms 후 저장합니다. 닫기·페이지 종료에는 최신 초안을 즉시 저장합니다. 전체 비교는 Web Worker에서 계산해 카드·근거·달력·집계에 공유하며, 이전 카드와 펼친 근거를 유지하고 오래된 계산 응답은 폐기합니다. 포커스 복귀만으로 조회하지 않습니다.

검증과 성능 수치는 [v6 검증 기록](docs/profile-v5-validation.md)에 있습니다.

### 마감일·지역 배정·내 가점·자녀 사실

- 종료되지 않은 접수 유형의 가장 이른 공식 종료일로 정렬합니다. 하루 접수는 그 날짜를 사용하고, 상시 접수 등 마감일이 미공개인 공고는 뒤에 표시합니다. 현재 접수 중인 공고도 같은 목록에 두고 배지로 구분합니다. 달력은 원래 접수기간을 표시합니다.
- 카드의 ‘지역·가점 당첨 기회’에서 해당지역 우선, 기타지역 별도 배정 물량과 일반공급 1순위의 주택형별 가점·추첨 비율을 보여줍니다. 가점제 100%의 동점자 처리와 추첨 배정 물량은 구분하며, 지역을 확인하지 못하면 불리함을 단정하지 않습니다. 기회 안내는 자격 판정·회색 표시·건수에서 공고를 제거하지 않습니다.
- ‘내 조건 설정 → 청약통장 → 일반공급 내 가점 비교’에서 기존 생년월일·혼인·소유·통장 입력을 재사용하고 필요한 가족 인정 사실만 추가합니다. 무주택기간 32점, 부양가족 35점, 통장 17점을 공고 기준일로 계산합니다. 미확인 항목이 있으면 총점을 확정하지 않습니다. 60세 이상 부모 소유 예외는 가점용 부양가족 인정과 별도입니다.
- 같은 공고·주택형·지역·가점제 경로·기준일의 공식 당첨 최저가점이 있을 때만 비교합니다. 다른 사업의 결과로 당첨확률을 추정하지 않습니다. 경쟁률 수집 주기에 당첨가점 API `getAptLttotPblancScore`와 공식 공개 결과 표를 확인합니다. 결과 미공개·수집 실패를 0점으로 바꾸지 않습니다.
- ‘내 조건 설정 → 특별공급’의 **계속 자녀·임신 없음**은 직접 선택했을 때만 두 사실의 변경 이력 없음으로 저장합니다. 기존 ‘현재 없음’은 과거에도 없었다는 뜻으로 바꾸지 않습니다. 확인되면 다자녀 조건을 0명으로 비교하고 반복 날짜 질문을 제거합니다. 현재 자녀 없음이면 생년월일·입양·추가 버튼, 임신 없음이면 태아 수를 숨깁니다. 실제 자녀·입양·임신 이력은 유지합니다.
- 목록·상세 API의 `selection_methods`에는 선정 비율·지역 배정과 적용 유형·주택형·기준일·원문 위치·문서 해시가 포함되고, `winning_scores`에는 공식 당첨가점·지역·출처·수집 상태가 포함됩니다. 개인 점수와 자녀·가족 이력은 서버에 보내지 않습니다.

공식 공고 대조, 재처리와 성능 측정은 [마감일·기회·자녀 질문 검증](docs/deadline-opportunity-validation.md)에 기록합니다.

상시 접수, 가점 기준일, 자녀·임신 이력과 당첨가점 수집을 보완한 후속 결과는 [2026-10-06 구현·검증](docs/continuation-v7-2026-10-06.md)에 있습니다. 이번 클라우드 환경의 검증 데이터와 이전 실제 공고 대조를 구분해 기록합니다.
