# 신청 요건·지역 판정·오늘 상태 비교 수정

인천가정2에서 확인한 요건을 모두 충족해도 일반적인 원문 검토 문구 때문에 판정이 보류되던 문제를 수정했습니다. 입력 부족, 과거 사실 미확인, 서비스의 원문 검토 부족을 구분하며, 서비스 사유는 공고당 한 번 표시합니다. 계약일 조건은 한국 시간 오늘의 상태로 미리 비교합니다.

인천가정2의 전체 19쪽을 검토한 기록을 문서 해시 `acef66815d56e98917f7d3ae2129de9dc6aede9827a4d79a948530373c66ea54`에 연결했습니다. 성년·미성년 세대주, 해외 생업 예외, 주택 소유 예외의 분기와 청약통장·소득·자산·과거 당첨의 면제를 구분합니다. 비교 가능한 일반공급 필수 요건은 연령, 국내 거주, 국적, 무주택, 해외 연속체류, 최초 당첨 후 계약에 따른 소유, 전매 위반 제한의 7개입니다. 해당 분기의 요건을 모두 충족하면 `조건상 가능성 있음`을 표시합니다.

해외 연속체류는 공고일 현재 해외에 있는 경우에 비교하며, 같은 국가로 7일 이내 재출국한 기간을 포함합니다. 90일 이하의 체류는 공식 국내 거주 인정 조건을 지역 판정에도 재사용합니다. 90일 초과의 생업 예외에는 국내에 있는 확인 대상 가족이 필요하며 단독세대주·동거인 세대원 제외 조건을 적용합니다. 공고일 전에 귀국한 사람을 과거의 긴 체류만으로 제외하지 않습니다.

최초 당첨·부적격 이력만으로 제외하지 않습니다. 같은 사업의 최초 당첨 후 계약이 있으면 계약으로 취득한 주택·권리를 공통 주택 이력의 사업번호, 취득·처분 사실과 연결해 소유 여부를 비교합니다. 다른 사업의 주택이나 같은 날 취득한 다른 주택을 대신 적용하지 않습니다. 60세 이상 직계존속 소유 등 공식 예외를 유지하며, 지분 이력만으로 실제 주택 수를 확정할 수 없는 경우에는 수에 의존하는 예외를 보류합니다.

단지 전체 308세대와 금회 모집 252세대를 분리했습니다. 금회 공급표는 74.9500A 18세대, 84.0000A 154세대, 84.0000B 58세대, 84.9800C 22세대입니다. 동일 블록 중복 신청·부부 예외는 신청 시 지킬 조건으로 표시합니다. 당첨 후 서류 제출·납부는 신청 자격 미확인 수에 포함하지 않습니다.

## 지역 수집과 남는 질문

청약홈의 이전 `Detail.do` 주소를 같은 공고번호의 현재 `DetailView.do`로 정규화합니다. 당산의 `static` 첨부 주소는 HTTP 200으로 59바이트 HTML 오류를 반환했습니다. 같은 경로·공고번호·첨부번호의 공식 `www` 주소에서 정상 PDF를 확보했고, 실제 재수집 해시 `99df9ab26e35d6af38b68c4d39f3d2d9b830460c232d77d725868a31dfda9804`와 날짜를 확인했습니다. 단지 주소나 과거 최초 공고로 지역을 추정하지 않습니다.

같은 문서 해시의 완전한 지역 검토는 부분 재처리에서도 보존합니다. 문서가 바뀌면 이전 해시의 조건을 재사용하지 않습니다. 확보·변환·판독에 실패하면 처리 단계와 미확보 항목을 표시하고, HTML 오류를 새 PDF 해시로 저장하지 않습니다. 새 첨부 확보 실패는 기존 비교값을 보존하면서 전체 판정을 보류합니다. 같은 첨부의 일시 실패는 기존 검토를 유지하며, 공식 재시도에 성공하면 처리 실패 경고를 해소합니다.

노부모부양의 부모 나이 60세가 65세 조건에 미달하면 그 경로의 추가 필수 질문을 중단합니다. 다른 공급유형은 계속 비교합니다. 생년월일·전입·혼인·취득·처분 날짜와 저장된 변경 이력을 재사용하고, 남는 질문은 `부양 시작일`, `세대주 상태 변경일`, `청약 제한 상태 변경일`처럼 실제 입력 항목에 연결합니다.

## 오늘 상태와 공식 계약기간

경산의 LH 공식 `#sta_ctrtDt` 계약기간 **2026-10-27~2027-08-31**을 수집해 목록·상세 API의 `contract_schedule`에 동일하게 제공합니다. 근거 URL·인용·원문 해시·위치를 보존하며, PDF의 '별도 공지까지' 문구보다 현재 공급정보의 명시된 기간을 우선합니다.

계약일 조건에는 개인의 예정 계약일을 묻지 않습니다. `오늘의 내 상태로 미리 비교`와 한국 날짜, 공식 계약기간, 실제 계약일까지 현재 상태가 유지된다는 전제를 표시합니다. 오늘 날짜와 개인 판정은 브라우저에서 계산하고 한국 시간 자정에 갱신하며, 전날의 캐시 판정을 다시 사용하지 않습니다. 모집공고일 기준 조건은 공식 기준일을 유지합니다.

## 검증과 적용 범위

API 256개 테스트와 웹 382개 테스트, production 빌드가 통과했습니다. [브라우저 139개 검사](qa/v9-browser-2026-10-07.json)에는 실제 원문을 재생한 인천가정2 충족·해외체류·당첨·계약·부모 소유 예외, 지역 복원, 질문의 실제 입력 연결, 실패 사유, 한국 자정 전환, 개인정보 미전송, 375px 표시, 마감일순 정렬·회색 공고·가격·경쟁률 유지가 포함됩니다. 부양 시작일 입력 후 35개월 불일치·36개월 충족과 다른 공고에서 같은 날짜의 재사용도 확인했습니다.

40개 공고·375px에서 [일반 입력 성능](qa/v9-performance-2026-10-07.json)은 입력 반응 p95 29.0ms·마지막 입력 후 전체 판정 468ms였습니다. [CPU 4배 제한](qa/v9-performance-slow-2026-10-07.json)에서는 입력 p95 72.1ms·전체 판정 630.4ms였고, 입력·클릭 전체 p95는 84.6ms였습니다. 두 조건에서 성능 검사 22개를 통과했습니다.

브라우저 검증에는 공식 원문과 구분해 표시한 QA 가상 접수 일정·가상 프로필을 사용했습니다. 검증 데이터는 실제 DB에 저장하지 않았고 보고서에 개인 프로필 값을 기록하지 않았습니다. [인천가정2 모바일 표시](qa/v9-screenshots/v9-gajeong-mobile-2026-10-07.png)와 [계약기간 모바일 표시](qa/v9-screenshots/v9-contract-mobile-2026-10-07.png)를 확인할 수 있습니다.

현재 클라우드 DB에는 SH 43건·GH 39건이 있고 지정 공고 7건은 없습니다. 원래 사용자 화면의 WSL DB는 이 실행 환경에 연결되어 있지 않습니다. [정확한 공고번호로 재처리한 결과](qa/conditions-v9-reprocess-2026-10-07.json)는 시도 0건·수정 0건·미보유 7건입니다. 이 원본 레코드가 재처리됐다고 보고하지 않습니다.

원래 DB에서 같은 수정본을 실행할 때에는 UUID를 다시 알아내지 않고 아래 명령으로 대상만 재처리할 수 있습니다. Gemini와 개인 프로필은 사용하지 않습니다.

```bash
python -m app.extract.reprocess \
  --external-id 0000061183 --external-id 2026000463 \
  --external-id 2026950085 --external-id 2026930033 \
  --external-id 2026910256 --external-id 2026950087 \
  --external-id 2015122300020823 --report /tmp/conditions-v9-reprocess.json
```

API·웹·worker의 Docker 이미지를 현재 클라우드 실행 환경에 적용했습니다. `/api/health`와 목록 API의 HTTP 200, 실행 중인 v9 파서와 3시간 수집 주기를 확인했습니다. 실제 웹·평가 worker 자산 해시는 브라우저 검증에 사용한 최종 production 빌드와 일치합니다. [실행·검증 기록](qa/conditions-v9-runtime-2026-10-07.json)

배포 전 기존 PostgreSQL 전체를 로컬 백업했습니다. [배포 전 기록](qa/conditions-v9-db-before-2026-10-07.json)과 [배포 후 기록](qa/conditions-v9-db-after-2026-10-07.json)을 대조해 공고 82건·접수 41건·원본 이력 135건·가격 및 경쟁률 테이블의 수와 내용 해시가 모두 동일함을 확인했습니다. [데이터 보존 결과](qa/conditions-v9-db-preservation-2026-10-07.json)를 저장한 뒤 수집 worker를 다시 시작했습니다. 이후 정상 수집은 새 공개 원본 이력을 추가할 수 있습니다. 포커스 복귀만으로 조회하지 않습니다.
