# 브라우저 자격 조건 규약

개인 입력은 API 요청·서버 로그·문서 추출에 사용하지 않습니다. 공개 API는 원문 공고의 조건과 근거만 반환하고 브라우저가 비교합니다.

## 공식 분류와 조건 분리

`housing_kind`는 `private`, `national`, `not_applicable`, `unknown`입니다. 청약홈 **APT**의 공식 `HOUSE_DTL_SECD` 01(민영), 03(국민) 또는 검토된 공식 문서로 분류합니다. 오피스텔·생활숙박시설처럼 아파트 민영·국민 구분의 대상이 아닌 건물은 `not_applicable`입니다. 무순위 아파트는 실제 민영·국민 종류를 유지할 수 있습니다. 다른 API의 같은 숫자, 공급기관, 분양 카테고리는 분류 근거가 아닙니다. 공식 출처가 충돌하면 `unknown`입니다.

`rank_applicability`는 주택 종류와 별개입니다. `status: applicable | not_applicable | unknown`, `account_required`, `reason`, 검증 상태와 원문·문서 해시를 제공합니다. 무순위·선착순·신혼희망타운의 별도 접수 방식과 오피스텔의 통장 불필요를 아파트 일반공급 순위로 바꾸지 않습니다.

`rules`의 `effect: "metadata"` 항목은 분류·조회 맥락이며 자격 조건이 아닙니다. `housing_classification`은 `housing_kind`와 근거를, `qualification_context`는 규제지역 등 명시된 사실을 담습니다. 공공주택지구 여부를 공공주택 특별법 적용 여부로 바꾸지 않습니다. 미공개 값은 `null`이고, 전체 자격 조건 확인을 뜻하지 않습니다.

## 검증·범위·기준일

조건은 `verification: "official"` 및 공식 근거가 있어야 비교합니다. AI·자동 추출 후보는 `review`로 남습니다. `housing_kind`, `public_housing`, `unit_type`, `supply_type`, `valid_from`·`valid_until`(또는 `effective_from`·`effective_to`)로 적용 범위를 지정할 수 있습니다. 법령별 조건은 `applicable_law` 등에 원문 이름·조항을 보존합니다. 적용 범위와 시행기간이 불명확하면 원문 확인이 필요합니다.

`criterion_date` 또는 `reference_date`가 명시되면 그 날짜를 사용합니다. `criterion_basis: "announcement"`는 원래 공식 모집공고일을 사용하며, 정정문에서 기준일을 바꾸면 명시적인 공식 기준일을 제공해야 합니다. 해당 기준을 지원하지 못하면 날짜를 추정하지 않습니다.

전체 조건이 공식 검증되었을 때만 `rules_complete`를 인정합니다. 조건 부족·미입력·미검증·지원되지 않는 조건은 확인 필요입니다. 서비스가 조건을 수집·해석하지 못한 경우는 ‘공고 조건 정리 중’으로 표시하며 공식 공고가 조건을 공개하지 않았다고 단정하지 않습니다. 내부 `unpublished` 상태는 호환을 위해 유지합니다. 명확한 필수 조건 불일치는 다른 미확인 조건이 있어도 불일치로 표시하되 공개된 예외를 먼저 비교합니다.

`condition_coverage` 메타데이터는 문서 해시·파서 버전·실제 모집 공급유형·유형별 조건 확보 상태를 보존합니다. `scopes`의 공급유형·주택형별 `verified_rule_count`, `missing_topics`, `complete`를 제공하며, 일부 조건의 확보는 전체 자격 조건 확인과 다릅니다. 공식 검증된 범위의 `complete: true`만 해당 조합의 완전성 판단에 사용합니다. 동일 공통 조건은 한 번 표시하고, 확인된 실제 조합의 차이를 별도로 비교합니다.

브라우저 근거에는 조건 비교, 입력 부족, 수집·해석 부족, AI 후보, 선택 필요를 구분합니다. 빈 요구값·기준일에는 반복적인 안내 문구를 채우지 않습니다. AI 후보는 별도 참고 영역에 원문과 함께 표시하며 전체 가능 판정에 사용하지 않습니다.

## 분기와 예외

`kind: "all" | "any" | "not"`와 `conditions`로 분기를 표현합니다. 자식 조건도 각각 공식 검증되어야 합니다. `exceptions`는 공식 예외 조건 배열입니다. 예외가 미확인이면 기본 조건 불일치를 확정 제외 근거로 사용하지 않습니다.

다음은 형식 예시이며 실제 공고의 적용 조건이 아닙니다.

```json
{
  "kind": "any",
  "verification": "official",
  "supply_type": "공식 모집 유형",
  "housing_kind": "national",
  "applicable_law": "공식 원문에 명시된 법령·조항",
  "valid_from": "YYYY-MM-DD",
  "evidence_url": "공식 공고문 URL",
  "conditions": [
    {"kind": "marital_status", "value": "married", "verification": "official"},
    {"kind": "children_min", "value": 1, "child_age_max": 6, "verification": "official"}
  ]
}
```

## 민영·국민 순위

`purpose: "first_rank"`인 검증된 공고 조건에 민영 `private_rank_months`·`deposit_min_krw`, 국민 `national_rank_months`·`recognized_payments_min` 등을 제공합니다. 통장 종류·세대주·당첨 제한·적용 법령·예외도 해당 공고에 맞게 포함해야 합니다. `rank_rules_complete: true` 또는 공식 `rank_requirements` 메타데이터의 `complete: true`는 **전체 적용 요건이 검증되었다는 선언**입니다. 수집기의 공식 주택 분류만으로 이 값을 만들지 않습니다.

공식 전체 순위 요건이 없으면 법령의 기본 기간·횟수와 입력 사실을 참고 비교하되, 공고의 지역별 연장·예외를 확정하지 않습니다. 날짜 하나나 기본 기간 안내만으로 1순위를 만들지 않고 자동 2순위도 없습니다.

공식 `rank_requirements`의 `required_kinds`, `housing_kind`, `criterion_date`, `complete`는 순위 요건의 완전성만 선언합니다. 전체 신청 자격의 `condition_coverage.complete`와 독립적입니다. 각 순위 조건을 모두 충족하면 전체 신청 조건이 부분 확보 상태여도 `1순위 조건 충족`을 표시합니다. 주택형별 조건이 다르면 `deriveRank`에 주택형을 전달하며, 공고 전체의 임의 순위 하나로 대체하지 않습니다.

가격의 `exclusive_area_sqm` 또는 공식 `area_basis: exclusive`만 예치금 표·청약부금 면적 제한에 사용합니다. 기존 `area_sqm`의 공급면적을 전용면적으로 취급하지 않습니다. 예치금과 국민 납입 인정 내역의 기준일을 비교하고, 이전 날짜의 민영 잔액은 계속 유지한 사실을 요구합니다. 입력 금액·날짜를 바꾸면 이전 유지 답변을 초기화합니다.

제53조 소유 판정은 브라우저 프로필 v4의 보유 사실 목록으로 수행합니다. 적용 날짜·공급유형·실제 처분 완료·가격 기준을 따로 비교하며 예전 소유 예외 자기판정을 확정값으로 이전하지 않습니다. [12개 예외 경로와 사실 규약](ownership-rules.md)을 참고하세요.

## 특별공급과 신청 불가 표시

실제 모집하는 공급유형만 여러 유형으로 진단합니다. 연 소득과 월평균소득, 총자산과 부동산·자동차 기준은 서로 대체하지 않습니다. 유형명만 확보한 경우 혼인·자녀·소유·소득 등의 세부 조건은 아직 정리하지 못한 상태이며, 원문에서 추가로 확인합니다.

기타지역에 해당하는 공고별 1순위가 확인되고 주택형의 공식 해당지역 마감이 최신 자료로 확인됐을 때 그 주택형·일반공급 접수일을 신청 불가로 표시합니다. 개인 조건이나 마감 때문에 행·공고를 목록에서 제거하지 않습니다. 미입력·수집 부족·최근 실패·6시간 만료는 신청 불가로 확정하지 않습니다. 가격·원본 공고·경쟁률 이력을 계속 읽을 수 있습니다.

공식 `applicant_regions`는 신청 시도·시군구와 장기복무군인 등 예외, `local_priority`는 해당지역 기준일·거주기간을 제공합니다. 공식 기준일에 그 지역에 거주했는지 확인할 연속 거주 시작일이 없으면 해당 시도·도시·구의 날짜만 추가 질문합니다. 기준일 이후 전입했다면 당시 주소 이력 확인으로 남기고 현재 주소로 과거의 지역 충족·불일치를 확정하지 않습니다. 민영 예치금 표의 거주 시도 구분에도 같은 기준일 확인을 적용합니다. 다른 시도라는 이유로 기타지역에 넣지 않습니다. `regional_allocation`의 **일반공급** `all_local_first` 및 `local_share_percent: 100`과 공식 `first_closed`·해당지역 모집/접수 수를 함께 확인하면 명시적인 해당지역 마감과 별도로 기타지역 배정 기회 종료 근거를 만듭니다. 원래 경쟁률 결과는 그대로 보존합니다.

결과 탭은 통장 순위·6시간 제한과 분리해 공식 배정 기회 종료의 근거를 표시합니다. 경쟁률 행은 회색 배경·테두리·배지로 구분하며 모든 행과 가격을 유지합니다. `competition.proof_invalidated`는 관련 정정 뒤 재확인 실패·대기 중에도 유지하며, 무효화된 근거로 신청 불가를 확정하지 않습니다. 개인 조건의 불가 항목도 표시 건수와 더 보기에 포함합니다.

## 로컬 문서 파서와 원문 이력

공식 공개 문서의 로컬 처리는 Gemini 키·무료 한도와 분리합니다. 검토한 문서 형식의 명시적인 기간·횟수·금액 표·가족 조건만 구조화하며, 문서 해시·페이지 또는 HWPX 구역·파서 버전·모집공고 기준일을 보존합니다. 조건을 읽지 못한 파일은 조건 미공개의 근거가 아닙니다. 문서가 교체되거나 공식 URL이 변경되면 이전 문서의 파서 조건은 현재 판정에서 제외하고 원본 변경 이력에 보존합니다.

민영 예치금 표는 신청 면적과 신청자의 거주지역을 함께 선택해야 비교할 수 있습니다. 여러 주택형의 면적 구간이 다르면 주택형별로 비교하며, 청약부금은 공식 문서의 전용 85㎡ 제한도 확인합니다. 기존 가격 행이 있다는 이유만으로 모든 특별공급과의 조합을 만들지 않습니다.

원문에 명시된 미지원 예외는 기본 조건의 불일치를 추가 확인으로 바꾸며, 예외 자체로 자격 충족을 인정하지 않습니다. 이는 거주지역의 조건 분기에도 적용됩니다. 검토된 공식 원문으로 조건을 확보한 상태와 전체 신청 요건의 검토 완료는 구분합니다.

보존된 공고의 로컬 조건만 다시 처리하려면 컨테이너에서 다음 명령을 실행합니다. 이 명령은 Gemini를 호출하지 않으며 한 번에 최대 100개 공고만 처리합니다.

```bash
docker compose exec -T worker python -m app.extract.reprocess --active --limit 50
```

특정 공고는 `--notice-id UUID`를 반복해 지정할 수 있고 `--dry-run`은 문서를 읽어 변경 결과만 계산합니다.

재처리는 문서 다운로드 후 공고를 다시 잠그고 최신 자료에 문서 조건만 합칩니다. 다운로드 중 정정된 공고의 일정·가격을 이전 조회값으로 덮어쓰지 않습니다. 공고별 저장과 이력 번호는 PostgreSQL 트랜잭션 잠금으로 보호하며, 정정 이전에 시작한 경쟁률 요청은 새 공고의 접수 제외 판단에 사용하지 않습니다.

## v4 가족 목록·무순위 신청 조건

프로필의 `householdMembers`는 이름 없이 가족 관계·본인/배우자 등본 위치를 저장합니다. 본인과 법률상 배우자는 별도로 포함하고, 제2조의 정확한 관계별 등본 조건으로 포함 여부·포함 이유·법정 확인 인원을 계산합니다. 배우자의 자녀·손자녀는 본인 등본에 함께 있을 때만 포함합니다. 본인·배우자의 등본이 실제 같은 등본이라면 배우자 등본에 있는 배우자의 자녀도 같은 본인 등본에 있는 것으로 처리합니다. 형제자매·동거인과 본인/배우자 어느 쪽에도 함께 있지 않은 부모·자녀는 등본만으로 포함하지 않습니다. [제2조 공식 세대 범위](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032749671)를 기준으로 검토했습니다.

본인이 등본에 등재되어 있는지, 배우자 유무, 실제 가족 관계·등본 위치와 목록의 완전성·기준일이 확보되어야 범위를 확정합니다. `householdScopeKnown`, `familyOnRegister`, 기존 `householdSize` 자기입력은 새 범위·인원의 근거가 아닙니다. `incomeHouseholdSize`는 소득 산정 가구원 수로 별도로 저장하며 법정 확인 인원을 대신하지 않습니다.

가족 목록 기준일보다 과거의 공고는 `householdHistoryConfirmations`에 해당 `criterionDate`의 실제 구성·등본 위치가 같은지 따로 답해야 합니다. 전체적인 `householdCompositionUnchanged` 답변이나 다른 날짜의 확인을 모든 과거 공고에 적용하지 않습니다. 기준일 이후 공고를 비교할 때는 해당 기간 동안 가족 구성·등본 위치가 유지되었는지 확인합니다. 가족 관계·등본 위치를 바꾸면 기존 날짜 확인을 초기화합니다.

`application_method`와 공식 `application_method_evidence`는 주택 종류·순위 적용과 별개로 무순위 사후접수, 임의공급, 계약취소 후 재공급 등을 구분합니다. 순위 적용 없음은 통장 비교만 생략하며 연령·지역·세대·소유·국적·해외 거주·사업별 당첨/계약·청약 제한 조건을 계속 비교합니다. 자격 기준일은 이번 접수의 공고일이며, `criterion_basis: original_announcement`인 조건만 최초 공고일을 명시적으로 사용합니다. 공식 미성년 예외가 아직 구조화되지 않았다면 나이 미충족만으로 확정 탈락하지 않습니다.

사업별 이력은 공식 최초 사업번호에 연결한 `projectApplicationHistory`로 저장합니다. 당첨·계약의 확인 대상 범위도 별도로 보존하며 다른 사업·다른 범위의 답변을 재사용하지 않습니다. 추가입주자 공급계약은 계약 이력과 함께 비교합니다. 부적격·공급질서 교란/전매 위반·재당첨 제한 조회는 `applicationRestrictionFacts`의 본인/본인·배우자/법정 세대 범위별 기록을 사용합니다. 기존의 포괄적인 신청 제한 답변을 새 조회 결과로 확정하지 않습니다.

국적은 공고의 공식 인정 국적과 비교합니다. 해외 거주는 출입국 사실에 근거한 연속 체류 일수(귀국 후 7일 이내 재출국 포함)와 생업을 위해 본인만 해외에 거주하고 가족은 국내에 있는 예외 사실을 구분합니다. 사업 이력·제한 조회·해외 일수에는 확인 기준일이 필요하며, 공고 기준일과 다르면 해당 날짜의 사실이 같은지 정확히 확인해야 합니다. 현재 결과를 과거 공고에 자동 적용하지 않습니다.

`household.test.ts`와 `qualificationV4.test.ts`가 별도 주소 배우자, 양쪽 등본의 부모·자녀, 배우자 자녀·형제자매, 불명확한 가족/소유 사실, 과거 구성, 법정·소득 인원 분리, 무순위 순위 독립성, 사업·범위·날짜별 제한 기록을 검증합니다.

검증된 공식 조건이 해당 공급유형·주택형 범위에 완전히 확보되어 있고 실제 공식 비교 조건이 있다면, 보존된 AI·자동 추출 후보를 별도의 필수 요건처럼 중복 적용하지 않습니다. 후보 원문은 접힌 참고 영역에 남깁니다. 공식 범위가 부분 확보 상태이거나 AI 후보만 있는 경우에는 신청 가능으로 확정하지 않습니다.

가족 입력의 배우자 유무와 혼인 상태는 하나의 사실 변경 경로로 처리합니다. 법률상 배우자가 있다고 답하면 혼인 중으로 동기화하고, 배우자가 없다고 답한 경우 예전 혼인 중 기록을 자동 미혼으로 바꾸지 않습니다. 배우자·혼인 상태·등본 위치·가족 목록이 실제로 바뀌면 과거 구성 확인과 가족 범위별 조회 기준일을 초기화합니다. 동일 답변을 다시 선택하거나 소득 등 다른 항목을 편집하면 유효한 가족 확인을 유지합니다.
