# v7 후속 구현·검증 (2026-10-06)

첨부 기록의 마지막 요청인 마감일순 정렬, 지역·가점 기회 안내, 자녀·임신 질문 수정을 기존 구현에서 이어서 완료했습니다. 이 기록은 2026-10-05의 실제 공고 대조 기록과 별개입니다.

## 보완한 동작

- 공식 자료가 상시·소진 시 접수임을 명시하고 종료일이 없으면 시작일 이후에도 목록·달력·후보 집계에 유지합니다. 카드에 종료일 미공개를 표시하고 날짜가 있는 공고 뒤에 둡니다. 단순히 종료일만 없는 하루 접수는 기간을 늘리지 않습니다. API, 현재 공고 재처리, 경쟁률 종료 판단도 같은 기준을 사용합니다.
- 과거 공고의 혼인·세대주·가점 사실은 각 사실의 저장된 이력을 사용합니다. 통장 인정기간의 2024년·성년 경계에서 월수가 잘리지 않도록 수정했고 배우자 통장 가점은 공식 시행일인 2024-03-25부터 적용합니다. [주택공급에 관한 규칙 제10조](https://www.law.go.kr/lsInfoP.do?lsiSeq=286965&viewCls=lsRvsDocInfoR)와 [국토교통부 시행 안내](https://www.korea.kr/news/policyNewsView.do?newsId=148927399)를 대조했습니다.
- 공식 가점·추첨 비율이 충돌하면 확정할 수 없다고 표시합니다. 근거가 없는 당첨가점은 비교하지 않고 잘못된 출처 URL 때문에 전체 계산이 중단되지 않게 했습니다.
- 당첨가점 API가 비거나 실패해도 현재 공식 공개 표의 점수를 보존합니다. API와 공개 표의 추가 주택형·지역을 합치고 충돌하는 공식 값은 비교를 보류할 수 있도록 보존합니다. 공고·주택형·순위·지역 식별과 목록·상세 응답 일치를 검증합니다.
- 자녀·입양·임신·태아 수 이력이 있으면 계속 자녀·임신 없음 선택으로 덮어쓰지 못합니다. 임신 이력 이전을 반복해도 기록이 늘어나지 않으며 다른 항목을 수정해도 독립적으로 저장된 배우자 여부를 바꾸지 않습니다. 중첩 공식 조건의 기준일과 근거를 입력 질문에도 적용합니다. 변경일 질문 링크는 해당 단계가 표시된 후 실제 자녀·임신 변경일 입력으로 포커스를 이동합니다.

## 이번 검증의 데이터 범위

이번 클라우드 작업 환경의 공고 DB는 처음에 비어 있었습니다. 이전 기록의 1,355건 데이터베이스는 이 환경에 첨부되어 있지 않아 해당 건수의 보존·실제 공고 대조를 다시 수행했다고 표현하지 않습니다. 기존 PostgreSQL 컨테이너와 데이터 디렉터리는 재사용했으며 삭제하거나 교체하지 않았습니다.

기관 인증키와 Gemini 키는 연결되어 있지 않습니다. 인증 API 출처는 연결 미설정으로 표시하고 SH·GH 공개 게시판 수집을 실행했습니다. 확보하지 못한 일정·가격을 만들어 채우지 않습니다. 현재 API 응답과 기관별 상태는 [실행 기록](qa/v7-runtime-2026-10-06.json)에 저장합니다. 현재 접수일이 확보된 재처리 대상은 [읽기 전용 점검](qa/v7-active-dry-run-2026-10-06.json) 당시 0건입니다.

최종 확인 시 SH 43건·GH 39건, 원본 공고·공고 이력 각각 82건을 저장했습니다. 확보된 주택형 가격과 접수 일정이 없어 현재 접수용 목록은 0건이며 두 게시판 출처는 일부 누락으로 공개합니다.

브라우저 검증은 저장된 공식 공고문·API 가격·경쟁률 표를 새 브라우저에 재생합니다. 일정·사업 연결·부하용 복제 공고는 QA 가상이라는 제목과 출처 기록으로 구분하며 실제 공고 DB에는 넣지 않습니다. 사용자 브라우저의 저장소를 읽지 않고 가상 프로필만 사용합니다. 이번 결과를 새로운 전국 실데이터 검증으로 보지 않습니다.

## 검증·적용 기록

- 웹 로직·표시 테스트 328개, API·파서·수집 테스트 215개를 통과했습니다. TypeScript와 production 웹 빌드, Docker API·worker·web 빌드가 성공했습니다.
- PostgreSQL의 독립된 임시 스키마에서 동시 수정, 최초 삽입 직렬화, 상시 접수 정규식 조회를 검증했습니다. 스키마는 검사 후 제거하고 실제 공고 테이블은 변경하지 않았습니다. [PostgreSQL 기록](qa/v7-postgres-2026-10-06.json)
- [브라우저 기능·개인정보 검증](qa/v7-browser-2026-10-06.json), [40개 공고 성능·저장 검증](qa/v7-performance-2026-10-06.json), [통합 결과](qa/v7-continuation-2026-10-06.json)에 이번 결과와 데이터 범위를 기록합니다.
- 브라우저 기능 검증 72개를 통과했습니다. 1280px·375px에서 17개 공고, 가격 8행, 경쟁률 8행과 26개 달력 날짜를 보존했고, 불일치 공고 6개도 회색으로 유지했습니다. 상시 접수의 이후 날짜 선택, 변경일 링크의 실제 포커스, 개인정보 미전송, 가상 프로필 저장과 가점 비교를 확인했습니다. [모바일 화면](screenshots/v7-opportunity-mobile-fixture-2026-10-06.png)은 저장된 공식 자료를 QA 가상 일정으로 재생한 모습입니다.
- 40개 QA 부하용 공고·375px·CPU 4배 제한에서 33회 입력·클릭 반응의 p95는 **72.4ms**, 마지막 입력 이후 최신 전체 판정은 **642.5ms**였습니다. 입력 반응 100ms 이하·전체 판정 1초 이내를 통과했습니다. 최초 데이터 준비 후 상호작용을 측정했으며, 해당 측정 구간에 메인 스레드 긴 작업은 없었습니다. 가격 16행·경쟁률 16행·달력 26일과 회색 공고 12개도 유지했습니다.
- 수정한 서비스는 이 클라우드 환경의 Docker에 적용했습니다. 공개 API와 웹의 `/api/health` 응답을 확인했습니다. 새 수집기는 3시간 주기를 사용하며 Gemini 실호출은 수행하지 않았습니다.

실제 전국 출시 검증에는 기관별 인증키 연결, 최신 실제 공고의 일정·가격 대조, 선택적으로 무료 티어 Gemini 실호출 확인이 남아 있습니다.

브라우저 검증 도구는 `--base`, `--snapshot`, `--today`, `--output`을 지원합니다. 브라우저의 실제 날짜를 사용하므로 이후 재실행할 때는 `build_portable_qa_snapshot.py`의 `--today`와 검증 도구의 `--today`를 현재 한국 날짜로 맞추어 스냅샷을 다시 생성합니다.
